# prothesis_logger

Simple MQTT logger that subscribes to topics and stores each message in PostgreSQL.

Each log row contains:
- `id` (from payload `id` when present, otherwise generated UUID)
- `received_at` (UTC timestamp generated by the app)
- `payload` (JSON message content)

## Tech stack
- Python 3.12
- MQTT client: `paho-mqtt`
- Relational database: PostgreSQL 16 (`jsonb` payload)
- Local broker: Eclipse Mosquitto
- Runtime/orchestration: Docker Compose

## Local run

1. Create `.env` from example:

```bash
cp .env.example .env
```

On Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

2. Start all services:

```bash
docker compose up --build
```

3. Publish a test MQTT message:

```bash
docker compose exec mosquitto mosquitto_pub -h localhost -t prothesis/logs -m '{"id":"msg-001","temperature":36.8}'
```

4. Query logs in PostgreSQL:

```bash
docker compose exec postgres psql -U prothesis_user -d prothesis_logger -c "SELECT id, received_at, payload FROM message_logs ORDER BY received_at DESC LIMIT 10;"
```

## Migrations

`db/init.sql` runs only when PostgreSQL data volume is created for the first time.
For schema changes after that, run SQL files from `db/migrations` manually.

Run the commands table migration:

```powershell
Get-Content .\db\migrations\20260323_001_create_commands_table.sql -Raw | docker compose exec -T postgres psql -U prothesis_user -d prothesis_logger
```

Check result:

```powershell
docker compose exec postgres psql -U prothesis_user -d prothesis_logger -c "\d+ command_logs"
```

## Configuration
All config is done with environment variables in `.env`.

- `MQTT_HOST`, `MQTT_PORT`, `MQTT_USERNAME`, `MQTT_PASSWORD`
- `MQTT_RAW_TOPIC` (comma-separated)
- `MQTT_QOS`
- `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`
- `LOG_LEVEL`

## Cloud migration (same app image)
For production/cloud, keep this Python app unchanged and switch only endpoints/credentials:

1. Broker options (managed MQTT):
   - HiveMQ Cloud
   - EMQX Cloud
2. Database options (managed PostgreSQL):
   - Neon
   - Supabase
   - Railway

Then set cloud values in environment variables (including auth/TLS settings if needed).

## Notes
- This MVP is designed for readability and easy setup.
- Works on different OS and CPU architectures through Docker images.
- For higher throughput in the future, add batching/queueing before DB insert.
